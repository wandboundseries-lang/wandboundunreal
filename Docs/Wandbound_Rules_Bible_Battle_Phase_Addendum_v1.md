# Battle Phase Addendum v1

Owner-approved authority, superseding legacy terminology only for the Battle
envelope defined here.

A Battle Phase is a temporary phase that begins immediately after a player legally
Declares an Attack. The Battle Phase contains the full resolution of that Declared
Attack, including its reaction windows, damage processing, triggered battle effects,
Counter eligibility, and any resulting Counterattack. A Counterattack does not
begin a new Battle Phase. The Battle Phase ends when the attack continuation and
any resulting Counterattack have completely resolved or been canceled. If the match
becomes terminal during the Battle Phase, the Battle Phase ends with the match
instead of returning to the Action Phase.

While a Battle Phase is active, normal Action Phase actions cannot be Declared
unless a rule or effect specifically permits that action during the current
Battle timing.

Battle is nested inside Action, not a once-per-turn segment. Multiple legal
Declared Attacks can each create a separate Battle during one Action Phase.
Nonterminal completion or cancellation resumes ordinary Action behavior.
PreHit, PostHit, and nested React windows stay inside the same Battle.
Accepted declarations create Battle even if later prevented or canceled.
Rejected declarations do not create Battle.

Existing damage stages, AfterDamage processing, Counter eligibility, and reaction
priority are unchanged. Counter is an Attack, not a Declared Attack, and stays
in the original Battle without creating counter chains.

Only player-declared root attacks create Battle in this foundation. NPC,
automatic, and effect-generated roots and standalone status/Trap/effect damage
remain excluded. An automatic Counter of a player-declared root belongs to that
root Battle.

DuringBattle and OutsideBattle are conditions only, not activation permission.
This addendum defines no new response timing or between-stage priority.
Battle-end triggers and once-per-Battle usage remain deferred.
